## 信息架构与交互变化

- 对话仍在左栏，但模型每轮最多展示一个关键问题；
- 快捷选项是可选回复，不再要求填完一组表单后提交；
- 用户可以直接自由输入，或点击“交给 Agent 决定”；
- 右栏 CTA 从两步改为“确认 Brief 并生成视觉方案”；
- 方案选择后的 CTA 明确写出“确认方案并生成效果图 · 1 次”，不隐藏费用动作；
- 中栏继续保持固定画布，不因从需求、方案、效果图切换而改变窗口尺寸。

## 2026-08-02 实测诊断

- 本地 Vite 的 `/api` 默认代理到 `https://3d-std.851241233.workers.dev`；
- 线上静态包仍是 M1.15a，不含 M1.16b、`deepseek-v4-flash`、单问题交互或新视觉方案链路；
- 因此前端收到的是旧 Worker 的 HTML 回退页，截图中的“无法解析”不是大模型能力失败；
- 已为 Agent、参考图、视觉方案和效果图接口增加 JSON 响应类型保护，遇到同类情况将明确提示“页面与服务版本不一致”；
- M1.16b 前后端必须作为同一个发布单元部署后，才能进行真实链路验收。

## 自动拆件故障边界（2026-08-02）

- 当前 Worker 使用 Hi3D 官方公开的 `/segmentation/create-task`、Token 鉴权、`mesh`、`seg_level` 与 `format` 参数；现有证据不支持“接口路径过期”的判断；
- 上传文件为浏览器从当前模型导出的二进制 STL，23.5 MB，低于公开文档 200 MB 上限；模型面数也低于现有应用的导出上限；
- 失败发生在提交阶段，界面没有收到 Hi3D `task_id`，因此不是轮询或结果导入错误；
- 当前错误响应只显示统一的退款提示，没有保留上游 `HTTP 状态 / code / msg` 给界面，无法仅凭截图区分鉴权、流式上传、模型解析或上游超时；
- 下一次受控测试前应先补充脱敏诊断信息，再决定保留 Hi3D 还是迁移混元，避免重复消耗拆件额度。
