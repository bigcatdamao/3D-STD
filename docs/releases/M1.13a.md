## 用户问题与产品目标

原图生模型链路使用其他第三方服务，无法直接复用同一供应商完成语义拆件。M1.13a 将生成 Provider 切换为 Hi3D，并先建立一套服务端接口，让同一组 AK/SK 可以分别调用：

1. 单图 / 多视角图片生成 GLB；
2. GLB、STL、OBJ 模型语义拆件；
3. 任务轮询与结果文件代理；
4. 失败返还、访客配额和全局成本熔断。

本版目标是打通真实服务端契约，不把“鉴权成功”描述成“拆件效果已经验收”。

## 已完成能力

### 1. Hi3D 共用鉴权客户端

- AK/SK 使用 Basic Auth 换取短期 access token；
- token 只在 Worker 内存中短时缓存；
- 图生模型请求使用 `Bearer`，拆件请求按官方契约使用 `Token`；
- 收到 401/403 时强制刷新 token 并仅重试一次；
- 浏览器网络响应、Git 文件和日志均不包含 AK、SK 或 access token。

### 2. 图生模型 Provider 切换

- `ENGINE_MODE` 改为 `hi3d`；
- 支持单图与多视角图片输入；
- 多视角按正、后、左、右顺序组装，并生成 `multi_images_bit`；
- 默认模型 `hitem3dv2.1`，分辨率 `1536fast`，输出 GLB；
- 当前 Hi3D 公共接口不提供文生 3D，前端从 `/api/health` 读取能力后隐藏文字模式；
- Hi3D 采用一组 AK/SK，旧版浏览器单 Key 自带通道在该 Provider 下关闭。

### 3. 真实拆件 Worker API

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/split` | 上传一个 GLB、STL 或 OBJ，提交 Hi3D 拆件任务 |
| `GET /api/split/:taskId` | 查询排队、处理中、成功或失败状态 |
| `GET /api/split/:taskId/result` | 由 Worker 代理下载临时 GLB 结果，不把上游临时地址暴露为产品接口 |

提交字段：

- `mesh`：模型文件，最大 200 MB；
- `segLevel`：`low`、`medium` 或 `high`；
- `turnstileToken`：人机验证 token。

当前配置为每访客 2 次/日、每次按 20 credits 记账、拆件全局熔断 200 credits。提交失败或任务失败时沿用幂等返还机制。

### 4. 前端生成入口适配

- `/api/health` 新增 `generationTypes`；
- Hi3D 模式只显示“单图”和“多图”；
- 若旧本地状态停留在文字模式，自动切换到图片模式并保留可理解提示；
- 不向浏览器返回 AK/SK，也不接受用一个前端 Key 冒充 Hi3D 的 AK/SK 对。

## 接口与数据结构变更

- `HealthResponse.config.generationTypes?: GenerateType[]`
- `SplitLevel = 'low' | 'medium' | 'high'`
- `SplitSubmitResponse`
- `SplitTaskResponse`
- Worker 环境变量：
  - 非密钥：`HI3D_MODEL`、`HI3D_RESOLUTION`、`HI3D_FACE_COUNT`、`HI3D_TIMEOUT_MS`
  - 配额：`HI3D_SPLIT_DAILY_LIMIT`、`HI3D_SPLIT_BREAKER_CREDITS`、`HI3D_SPLIT_COST_CREDITS`
  - Cloudflare Secrets：`HI3D_ACCESS_KEY`、`HI3D_SECRET_KEY`

## 安全与隐私边界

- `Hi3D.txt` 仅被用于本机只读鉴权验证，没有复制进项目；
- `.dev.vars` 与 `.dev.vars.*` 已加入 `.gitignore`；
- 本轮没有在项目内持久化密钥；两项凭证已作为 `HI3D_ACCESS_KEY`、`HI3D_SECRET_KEY` 写入 Cloudflare Secrets；
- 拆件时用户模型会上传到 Hi3D，这是后续 UI 必须明确告知并确认的外部处理行为；
- 上游结果 URL 有时效性，产品只通过 Worker 代理读取，后续正式版仍需评估 R2 持久化策略。

## 真实能力边界与已知问题

1. 本机已真实调用官方 token 接口并返回 HTTP 200，证明 AK/SK 有效；
2. 为避免未经确认消耗 credits，本轮没有提交收费的图生模型或拆件任务；
3. `/api/split` 后端已完成，但当前工作台尚未增加“选择当前对象 → 确认上传 → 预览拆件 → 导入结果”的前端闭环；
4. 尚未通过真实返回 GLB 验证结果内是多个独立节点、多个网格还是单一场景容器；
5. 只有完成一次真实拆件、导入场景并核对独立选中/导出后，才能确认它满足产品拆件闭环；
6. 本版不会删除或替换原始模型，未来导入拆件结果也必须保留源对象副本。
