## 决策背景

- M1.16b 已由用户在生产环境跑通文字需求、视觉方案、效果图、三视图与 Hi3D 成模；
- Hi3D 自动拆件在获得任务 ID 前失败，但现有界面没有暴露上游 `HTTP/code/msg`，目前不能把单次失败归因到一个确定错误码；
- Hi3D 当前公开拆件协议仍为 `/segmentation/create-task` + Token + `mesh/seg_level/format`，与现有实现一致；
- 混元生 3D 同时提供多视图生成与组件生成 API，适合作为下一阶段的同供应商闭环候选；
- 本版先稳定供应商链路与可诊断性，完整 UI/体验重设计放在供应商能力验证之后。

## 推荐发布策略

不直接删除 Hi3D。新增供应商抽象与功能开关，先让混元在测试环境完成真实闭环，再决定生产默认值：

1. `GenerationProvider`：统一提交、查询、取消/失败、结果文件和费用信息；
2. `PartProvider`：统一提交、查询、失败信息、组件结果与分割元数据；
3. Hi3D 适配器保留为可回滚路径；
4. 混元适配器通过服务端环境变量启用，不向浏览器暴露 SecretId/SecretKey；
5. 每个供应商响应保留脱敏 `provider`、`requestId/taskId`、`errorCode` 与阶段，便于真实环境定位。

## 混元目标链路

1. 用户确认三视图；
2. Worker 使用 `SubmitHunyuanTo3DProJob` 提交混元 3.1 多视图生成；
3. 生成阶段请求 FBX，作为后续组件生成的输入；
4. 用户查看并明确接受 3D 结果；
5. Worker 使用 `SubmitHunyuan3DPartJob` 提交 FBX 组件生成；
6. 使用 `QueryHunyuan3DPartJob` 轮询 `WAIT/RUN/FAIL/DONE`；
7. 成功后优先导入结果中的 OBJ/FBX，并保存 `PartSegmentationInfo`；
8. 零件作为独立对象进入场景，原始模型副本保留，操作写入历史并可撤销。

## 必要技术改动

- 新增腾讯云 API 3.0 的 TC3-HMAC-SHA256 服务端签名客户端；
- 新增 `TENCENTCLOUD_SECRET_ID`、`TENCENTCLOUD_SECRET_KEY`、`HUNYUAN_REGION` Secrets/变量；
- 多视图参数映射到 `MultiViewImages.N`，并控制 Base64 总体积不超过官方限制；
- 生成请求固定 `Model=3.1`、`ResultFormat=FBX`，面数由打印用途和成本配置决定；
- 组件生成只接收 FBX，需要增加 FBX 结果缓存/透传与前端预览解析；
- 统一供应商 JobId、RequestId、状态、结果 URL 有效期、失败码和退款策略；
- 增加超时、轮询恢复、刷新后续查、结果 URL 过期和供应商熔断处理；
- 不在前端、Git、日志或浏览器响应中返回腾讯云密钥。

## 开发任务

1. 先给现有 Hi3D 拆件响应补充脱敏诊断字段，完成一次小模型与一次真实模型对照；
2. 建立 provider-neutral 的生成/拆件类型与状态机，保持现有 UI 不变；
3. 实现并单测腾讯云签名、提交与查询客户端；
4. 接入混元 3.1 多视图成模，验证 FBX 结果；
5. 接入混元组件生成与组件结果导入；
6. 将配额、退款、熔断和历史操作迁移到统一供应商层；
7. 用同一组人物、机甲、简单物体做 Hi3D/混元对照评测；
8. 混元真实闭环通过后再切换生产默认供应商。

## 验收标准

- 三视图提交后返回可追踪的 JobId/RequestId，刷新页面可继续查询；
- 成模成功后能在场景中预览，模型来源和供应商状态明确；
- 用户确认后再提交组件生成，不自动产生第二次付费；
- 组件生成得到至少 2 个可独立选择、移动、隐藏和导出的零件；
- 原始模型不被覆盖，接受结果写入历史并支持一次撤销；
- 失败时展示用户可理解的阶段提示，并保存脱敏错误码用于排查；
- 人物、机甲、简单物体三类 Gold Set 均至少完成一次真实链路；
- 记录耗时、费用、零件数量、主观可用率与失败原因，作为是否永久替换 Hi3D 的依据。

## UI 重设计边界

M1.17a 只做供应商无关的状态和错误表达，不大改工作台。完成真实闭环后进入 M1.17b：重新设计对话、视觉确认、3D 结果、拆件确认和打印准备之间的连续体验。

- 新 SecretId/SecretKey 已通过 TC3-HMAC-SHA256 签名鉴权；
- `QueryHunyuan3DPartJob` 请求成功到达腾讯云，使用不存在的任务 ID 返回 `FailedOperation.JobNotExist`，证明密钥、签名、地域和查询权限有效；

- 官方组件生成入口确认为 `SubmitHunyuan3DPartJob`，版本 `2025-05-13`，输入仅支持 FBX；
- 官方计费规则确认：组件生成消耗 30 积分/次；失败任务不扣积分。

### 首次阻塞（已解除）

- `SubmitHunyuanTo3DProJob` 返回 `ResourceInsufficient`，RequestId：`5bd430be-aae8-4411-8b9c-75286d427884`；

### 恢复条件与下一次最小测试

1. 在腾讯混元生 3D 控制台领取一次性 100 免费积分，或明确开启后付费；
2. 重新提交一次 `Geometry + ResultFormat=FBX` 的简单双部件模型，预计 20 积分（15 + 5）；
3. 成模成功后，将返回的 FBX 直接提交组件生成，预计 30 积分；
4. 预计最小完整验证共 50 积分，不开启 PBR、不指定 FaceCount、不启用组件后处理；
5. 保存生成与拆件的 JobId、RequestId、耗时、结果文件类型、零件数和主观质量，完成供应商对照记录。
