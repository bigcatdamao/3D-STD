## 用户问题

- 已有效果图的用户必须经过 Agent 对话，缺少直接图生模型入口；
- Agent 与快捷生成之间的入口关系不够清晰；
- 本地导入的 STL/GLB 没有混元生成任务和 FBX 来源，却可能进入旧 Hi3D 自动拆件链路；
- 如果现在为所有导入格式建设 STL/GLB/FBX 转换、临时云存储和清理服务，会偏离作品集 Demo 的主线。

## 产品决策

当前作品集先打通两条一级创作路径：

1. **3D 创作 Agent**：模糊需求 → 对话澄清 → 效果图/多视图 → 混元 3D 成模；
2. **已有图片成模**：上传单图或多视图 → 混元 3D 成模。

后续共同进入：

`生成模型 → 自动拆件 → 榫卯与公差 → 打印检查 → STL 导出`

自动拆件本轮只接受混元生成阶段保留下来的 `hy3d_` 任务。用户本地导入的模型仍可预览、编辑、手动拆件、检查和导出，但缺少混元 FBX 来源时不提供自动拆件，也不静默降级到 Hi3D。

## 功能与交互变化

- 创作工作台增加尺寸稳定的双入口：`3D 创作 Agent`、`已有图片成模`；
- “已有图片成模”使用独立两栏页面：左侧说明，中央提供大面积图片点击/拖放区；
- 复用既有单图、多图、上传校验和混元提交能力，不复制生成状态；
- 支持 `?qa=image-to-3d` 直接打开图生模型入口，便于 QA 与作品集演示；
- Agent 工作台原三栏结构保持不变，切换入口不再改变顶层页面尺寸；
- 自动拆件入口仅接受 `engine=hunyuan` 且任务号以 `hy3d_` 开头的资产；
- 本地导入或旧供应商资产会提示使用“手动拆件”，并说明通用转换属于后续商业化选型；
- 旧 Hi3D 拆件实现保留在代码中供历史追溯，但不再作为生产 UI 的自动降级路径。

## 文件格式边界

既有混元真实冒烟结果同时返回 GLB 与 FBX：

- GLB 用于浏览器预览、落场和后续网页编辑；
- FBX 通过混元生成任务保留，交给组件生成接口完成拆件；
- STL 是最终打印导出格式，不需要为了这条主链路先转换为 FBX。

本地 STL/GLB 自动拆件需要额外建设转换、对象存储、签名 URL、任务清理、单位与法线校验。本版本明确暂缓，相关选型见：

- `docs/model-provider-selection.md`；
- `docs/prompts/3d-model-provider-selection-research.md`。
