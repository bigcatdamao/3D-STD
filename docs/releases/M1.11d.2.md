## 问题证据

用户在同一 1,499,346 面模型上粗涂 146,272 面后执行自动补全，错误结果扩张为
1,499,345 面，仅剩 1 面未选；随后又因为超过 500,000 面安全预算而失败。

这不是模型损坏。根因是候选闭环只检查了粗涂覆盖率，没有限制候选区域占模型比例和
补全膨胀倍数；同时失败的接缝验证结果仍携带补全面组并被前端写回。

## 本版修复

- 自动补全区域不得超过 500,000 面；
- 自动补全区域不得超过模型总面的 85%；
- 补全上限按粗涂面数动态计算，默认最多约 4 倍，并为小范围粗涂保留 20,000 面余量；
- 候选必须覆盖至少 60% 的原始粗涂；
- 不安全候选返回明确提示，并保留原始粗涂；
- Worker 接缝验证失败时不再返回补全面组；
- 前端只在接缝状态为 `ready` 时写回补全结果；
- 面板版本标识更新为 `M1.11d.2 · 安全自动补全`。

## 回归覆盖

- 接近全模型的候选必须以 `unsafe_expansion` 失败；
- 失败信息明确说明原始粗涂已保留；
- 即使异常 Worker 返回了补全面组，前端也不能覆盖原面组；
- 原有隐藏面补全、10 万面以上非索引模型和接缝 Worker 测试继续通过。

## 验证结果

- `npm.cmd run typecheck`：通过；
- `npm.cmd test -- --run`：62 个测试文件、497 项测试通过；
- `npm.cmd run build`：通过；仅保留项目既有的主包体积提示。

## 真实模型复测

1. 重新进入面组模式；
2. 粗涂与问题截图相同的约 14.6 万面局部区域；
3. 点击“自动补全并分析”；
4. 若没有可靠的小范围候选，应显示安全拒绝，粗涂面数保持约 14.6 万；
5. 若找到可靠候选，补全后不得接近全模型，并进入绿色单闭环预览；
6. 验证 `Ctrl+Z` 仍可退回补全前粗涂。
