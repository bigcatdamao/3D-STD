## 用户问题与产品目标

M1.16a 虽然有完整工作台外形，但 Agent 仍像固定问卷，快捷选择会出现空回答，用户一直停在需求确认。M1.16b 的目标是让自由语言成为主路径，让 Agent 真正理解信息、只追问必要内容，并用清晰的用户闸门继续到视觉方案和效果图。

## 新增与修改

- 需求对话切换为 AIHubMix `deepseek-v4-flash`；
- DeepSeek 使用 OpenAI Chat Completions + JSON Object，Worker 对结果继续执行严格字段校验；
- 显式关闭默认思考模式，避免模糊需求消耗大量推理 token 后被截断；
- 视觉方案继续独立使用 `gpt-5.6-sol` strict-schema 路径，避免一个协议变化阻断整条链路；
- 每轮最多追问一个会改变结果的问题；自由输入始终可用；
- 快捷建议改为点击即回复，并增加“交给 Agent 决定”；
- 问题新增 `targetField`，支持模型生成任意 `questionId`，不再依赖前端硬编码键；
- `readiness.missingFields` 只允许对象、类型、用途和风格作为视觉探索阻塞项；
- “确认 Brief”和“生成视觉方案”合并为一次明确点击；
- “确认视觉方向”和“生成效果图”合并为一次明确付费点击；
- M1.16a 的固定三栏布局、参考图、VLM、Hi3D 交接和安全闸门全部保留。

## 当前用户路径

1. 用户用任意自然语言描述想法，也可添加参考图；
2. DeepSeek 抽取完整 Brief，信息不足时只问一个关键问题；
3. 用户可点快捷建议、自由回答或交给 Agent 决定；
4. Brief 达到视觉探索最低条件后，用户点击“确认 Brief 并生成视觉方案”；
5. LLM 返回三套可比较方向；
6. 用户选择方案并点击“确认方案并生成效果图 · 1 次”；
7. 用户检查效果图，可继续单图成模或生成三视图后多图成模；
8. Hi3D 仍有独立的费用确认，接受结果后才进入场景。

## 接口与数据变化

- `CreationAgentQuestion` 新增必填 `targetField`；
- `questions` 最大数量从 3 改为 1；
- 新增 `CREATION_AGENT_PROTOCOL=chat_completions`；
- `CREATION_AGENT_MODEL=deepseek-v4-flash`；
- 新增独立 `CREATION_CONCEPT_MODEL=gpt-5.6-sol`；
- DeepSeek 请求包含 `thinking: { type: "disabled" }`；
- Key 仍只从 Worker Secret 读取，不进入前端、仓库、浏览器响应或日志。

## 真实 API 验证

- 明确需求实调：一次提取原创成年女性 GK、`character`、`resin_print`、日式二次元、250 mm 和 Agent 建议站姿；`readiness=1`、无多余问题；
- 模糊需求两轮实调：第一轮只问 `style`，选择后发送完整非空摘要；第二轮只问 `purpose`，没有重复问题；
- 关闭思考模式后，两轮请求不再触发 2400/4000 token 截断；
- 视觉规划实调返回 3 套方案，推荐 ID 与三套标题完整；
- 未在开发者脚本中调用付费生图或 Hi3D，效果图与 3D 仍等待用户在 UI 明确确认。

- 用户在本地 M1.16b 页面完成需求对话和视觉方案操作，但两次请求均进入无法解析/本地降级；

- 根因确定为“新版前端 + 旧版 Worker”的发布版本不匹配，不是 DeepSeek 理解失败，也不是视觉方案模型质量失败；

- 修正后再次通过 `npm run typecheck`、生产构建和完整测试：75 个测试文件、550 项测试全部通过。

## 已知边界

- DeepSeek V4 是文本模型，参考图继续由独立 VLM 处理；
- 视觉方向是文字规划，只有用户点击付费按钮后才生成 PNG；
- 生成图不保证严格三视图一致性或最终 3D 可打印性；
- Hi3D、自动拆件、修复和导出仍是各自独立能力，不由对话 Agent 自主执行；
- 本版尚未部署，生产环境仍不是 M1.16b。
- 线上当前仍为 M1.15a，不能用于验收 M1.16b 的真实 Agent 链路。
