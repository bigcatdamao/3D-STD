# 3D Studio 版本存档规范

从 M1.12b 起，版本记录与真实 UI 截图是版本完成条件，不再作为可选补充。

## 每个版本必须交付

1. `docs/releases/<版本号>.md`：功能与工程记录；
2. `docs/ui-history/<版本号>/README.md`：UI 状态、截图索引和体验结论；
3. `docs/ui-history/<版本号>/01-overview.png`：完整工作台；
4. `docs/ui-history/<版本号>/02-entry.png`：功能入口；
5. `docs/ui-history/<版本号>/03-interaction.png`：关键编辑过程；
6. `docs/ui-history/<版本号>/04-result.png`：完成态、失败态或真实能力边界。

如版本没有某种状态，必须在 UI 记录中写明“不适用”，不能用概念图代替真实产品截图。

## 功能记录固定字段

- 日期、版本状态、上一版本；
- 用户问题与产品目标；
- 新增/修改/保留/移除的能力；
- 主要交互路径；
- 关键技术实现；
- 数据结构或接口变更；
- 真实能力边界和已知问题；
- 自动化与手动验证；
- Git 提交、远程上传、部署地址；
- 回滚方式和下一步。

## UI 记录固定要求

- 必须来自该版本实际运行页面，不使用 AI 生成图或设计稿冒充；
- 记录浏览器、视口尺寸、缩放比例和测试对象；
- 截图保留完整产品上下文，局部放大图只能作为补充；
- 图中必须能识别版本、入口、关键操作状态和结果；
- 每张图写明“用户做了什么、系统反馈了什么、这张图证明什么”；
- 涉及密钥、账号、私有文件名时必须遮蔽；
- UI 改动必须同时记录信息架构、控件、文案、状态和视觉层级。

## 版本状态定义

| 状态 | 条件 |
| --- | --- |
| 开发中 | 功能、验证或截图任一未完成 |
| 本地候选版 | 功能实现、自动化验证和本地 UI 截图齐全 |
| 已提交 | 记录 Git commit |
| 已上传 | 记录远程分支和 commit |
| 已部署 | 记录生产 URL、部署时间和线上点测 |
| 已验收 | 用户明确验收并记录结论 |

功能记录存在但 UI 截图缺失的旧版本，统一标记为“历史功能记录存在，UI 待回补”，不能声称档案完整。

## 作为后续文档的数据源

- PRD：读取用户问题、目标、用户路径、验收标准和能力边界；
- 技术文档：读取模块、状态、算法、Worker、数据结构和验证结果；
- 设计文档：读取 UI 截图、信息架构、状态变化、交互规则和体验结论；
- 发布说明：读取版本差异、已知问题、部署状态和回滚方式。

版本档案记录“该版本实际做成了什么”，未来文档可以据此整理，但不能补写当时没有实现或没有证据的能力。

## 本地截图辅助

项目提供 `scripts/local-ui-capture-receiver.mjs`，只监听 `127.0.0.1`，将浏览器返回的 PNG
限制写入指定的项目内目录，并在达到数量上限后自动退出。例如：

```powershell
node scripts/local-ui-capture-receiver.mjs --out docs/ui-history/M1.12b --port 4187 --limit 4
```

该脚本只负责保存真实页面截图，不生成或美化 UI。
