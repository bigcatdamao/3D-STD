## 用户问题

百万面模型进入“自动拆件”后，约 47.7 MB 的临时 STL 在提交阶段失败，页面曾显示
`Unexpected end of JSON input`，任务没有进入 Hi3D 排队状态。

## 根因

M1.13b 的 Worker 使用 `request.formData()` 读取完整模型，再构造第二份 multipart 请求上传至
Hi3D。大文件因此同时产生输入缓冲、File/FormData 对象和输出 multipart 缓冲。Cloudflare Worker
的 isolate 内存上限为 128 MB，47.7 MB STL 已进入高风险区，进程可能在返回 JSON 前被终止。

这不是 Hi3D 的 200 MB 文件上限，也不是语义拆件算法本身失败，而是本站中转层的上传实现问题。

## 修复

- 浏览器仍将临时 STL 编码为 Hi3D 所需的 multipart 字段；
- 人机验证 token、文件名、文件大小和粒度改由同源请求头传给本站 Worker；
- Worker 不再调用 `request.formData()`，原始 multipart `ReadableStream` 直接转发给 Hi3D；
- AK/SK 和短期 access token 仍只存在于 Worker；
- 流式正文不可重放，因此鉴权失败时清除 token 缓存、返还额度，等待用户显式重试；
- 前端保留空响应/非 JSON 响应的中文错误兜底。
