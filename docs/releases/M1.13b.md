## 用户问题与产品目标

M1.13a 已有 Hi3D 拆件后端接口，但用户仍然无法从当前模型主动完成拆件。M1.13b 将它接成可操作闭环：选择模型、确认外部处理与费用、提交任务、查看状态、下载结果、导入独立零件、自动打印检查。

本版只解决“得到可独立编辑的零件”，不把榫卯、公差和装配验证混入同一次操作。

## 用户路径

1. 在画布或场景树选中一个未锁定模型；
2. 点击工具栏“自动拆件”；
3. 在右侧确认源模型、面数、临时 STL 大小、拆件粒度、20 Credits 与 Hi3D 外部处理说明；
4. 人机验证完成后提交；
5. 查看排队、处理中、下载与解析进度；
6. 成功后源场景实例被多个独立零件原子替换，原始资产仍留在资产库；
7. 系统自动运行打印检查；
8. 可通过一次历史撤销恢复源实例。

## 已完成能力

- 工具栏同时明确显示“手动拆件”和“自动拆件”，不再用泛化的 AI 建议入口；
- 当前选中对象自动导出本地坐标系二进制 STL，不要求用户再次选择文件；
- 上传前展示文件大小、语义粒度、预计 Credits、外部处理和原资产保留规则；
- 接入 `POST /api/split`、状态轮询与结果代理下载；
- 新增独立 Worker 解析 Hi3D GLB，保留多个 Mesh 节点为独立零件；
- 按源资产包围盒统一归一第三方结果的单位、尺寸和中心；
- 新增 N 零件原子场景命令，一条历史即可撤销/重做；
- 下载、解析、节点不足、尺寸异常、场景等待期间被编辑时均失败关闭，不修改场景；
- 本地 Vite 将 `/api` 代理到已部署 Worker，候选 UI 可直接跑真实链路；空响应或非 JSON 响应转换为中文 HTTP 错误，不再暴露 `Unexpected end of JSON input`；
- 成功后自动启动打印检查。

## 关键工程实现

- `src/split/auto-split-state.ts`：提交、轮询、下载、导入和失败恢复状态机；
- `src/split/AutoSplitPanel.tsx`：右侧产品流程与状态反馈；
- `src/split/auto-split-result.worker.ts`：后台解析第三方 GLB；
- `src/split/auto-split-result-core.ts`：结果数量闸门与源空间归一；
- `src/importer/parse-core.ts`：新增保留 Mesh 节点边界的 `decodeGlbParts`；
- `src/kernel/scene.ts`：新增 `splitInstanceWithDerivedPartsMany` 原子命令。

## 数据与安全边界

- 临时 STL 在浏览器内生成，只在用户点击“开始自动拆件”后上传；
- API Key 仍只存在于 Cloudflare Secret，不进入前端包、网络响应或资产元数据；
- 任务结果通过本站 Worker 代理下载，不直接暴露上游临时 URL；
- 源资产不改写；场景只在结果成功解析且确认至少两个独立 Mesh 后发生一次原子替换；
- 等待期间若用户修改场景，结果不会自动覆盖当前工作。

## 真实能力边界与已知问题

1. 当前以 Hi3D 返回 GLB 的 Mesh 节点作为独立零件；若上游把所有语义部件重新合并成单一 Mesh，本版会拒绝导入；
2. 本版不生成榫卯、不设置公差、不执行装配验证；
3. 成功导入后每个零件会重新做打印检查，不能假设第三方结果天然水密；
4. 任务暂不支持取消上游计算；处理中只能等待，查询超时后可继续查询；
5. 真实 Hi3D 计费拆件尚未在本轮执行，因此独立节点结构、拆件质量与处理耗时仍需实测；
6. 浏览器外部控制通道本轮不可用，按存档规范不使用内置浏览器或概念图冒充真实 UI，截图仍待补齐。
